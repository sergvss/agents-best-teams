# Чек-лист: использование инструментов агента


---

## Перед вызовом любого инструмента

- [ ] Я знаю, зачем вызываю этот инструмент — у меня есть конкретная цель
- [ ] Я не вызываю инструмент «на всякий случай» или «чтобы посмотреть»
- [ ] Я оцениваю класс риска (R/D/W/P) — см. `../principles/03-risk-classes.md`
- [ ] Если класс W или P — у меня есть подтверждение пользователя

---

## Read / Glob / Grep — чтение файлов

- [ ] Читаю только то, что нужно для текущей задачи
- [ ] Если файл большой — начинаю с `limit:` 200 строк или `wc -l` сначала
- [ ] Не читаю `.env*` файлы — только если явно попросили и с осознанной целью
- [ ] Результат grep/glob не превышает 500 строк — если больше, уточняю паттерн

---

## Edit / Write — запись файлов

- [ ] Я прочитал файл перед редактированием (Edit требует этого явно)
- [ ] Правка минимальна — трогаю только то, что относится к задаче
- [ ] Не форматирую несвязанный код в том же изменении
- [ ] Не создаю новые файлы без явной задачи
- [ ] Файл `*.md` (документация, README) — создаю только если задача явно про документацию. Не плодить файлы «на всякий случай»
- [ ] Файл `.env*` — не создаю и не редактирую (класс P)

---

## Bash — выполнение команд

- [ ] Команда использует абсолютные пути, а не `cd` + относительные
- [ ] Вывод команды не превысит 500 строк — если может, использую `| head -200` или редирект в файл
- [ ] `find` — с `-type f -name '...'`, не голый `find .`
- [ ] `rm` — проверить дважды. `rm -rf .` → заблокирует hook, и правильно
- [ ] `git add` — только конкретные файлы, не `-A` и не `.`
- [ ] Деструктивная команда (drop, truncate, rm -rf) → сначала подтверждение

---

## Agent — вызов subagent

- [ ] Вызываю правильного агента по области задачи (не `general-purpose`)
- [ ] ТЗ сформулировано по HANDOFF-шаблону — есть контекст, задача, constraints, acceptance criteria
- [ ] Указал «что прочитать перед правкой» — агент не тратит контекст на поиск
- [ ] Учитываю бюджет делегаций текущего Tier

---

## MCP-инструменты (Playwright, context7, etc.)

- [ ] MCP-инструмент доступен — не виснет на недоступном сервере
- [ ] После завершения работы с браузером — `browser_close`
- [ ] Скриншоты сохраняются в правильную папку `tests/e2e/screenshots/`
- [ ] Не делаю скриншотов с видимыми credentials/JWT

---

## Общее правило: output size

| Ситуация | Действие |
|---|---|
| Bash stdout > 500 строк | `\| head -200` или редирект в файл |
| Read большого файла | Начать с limit: 200, потом по необходимости |
| git diff большого PR | `git diff --stat` сначала, потом точечно |
| Логи | `tail -100` или `grep -E 'pattern' \| head -50` |
| SQL запрос | `LIMIT 50` в запросах |
