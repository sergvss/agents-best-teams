# agents-best-teams и obra/superpowers

[obra/superpowers](https://github.com/obra/superpowers) — фреймворк скиллов и методика разработки Джесси Винсента. Большая часть нашего процесса разработки выросла из его идей: мы сравнивали их построчно, переносили по одной и мерили каждую до и после. Этот документ — что взято, что изменено, что отброшено и почему.

Сравнение по superpowers 7.0.1 и agents-best-teams 1.38.0, октябрь 2026.

---

## Короче всего

- **Процесс** — идея, план, ветка, тест, отладка, ревью, слияние — теперь есть в обоих. Наш короче: один раунд вопросов вместо интервью, ревью только там, где ошибка дорога.
- **Механическая защита** — только у нас: хуки останавливают разрушение, запись в `.env`, force-push и коммит без ревью, а не просят этого не делать.
- **Команда ролей с зонами** — только у нас: у каждого каталога один хозяин, и хук держит границу.
- **Платформы и масштаб** — у них: 16 платформ и сотни тысяч пользователей. У нас механика только для Claude Code.

Ставить два плагина вместе не нужно: наш закрывает весь путь сам. Несовместимости нет — проверено прогоном, — но два набора правил процесса в одной сессии спорят друг с другом.

## Этап за этапом

| Этап | superpowers | agents-best-teams | Почему у нас иначе |
|---|---|---|---|
| Как скиллы срабатывают | полный текст главного скилла в каждой сессии и правило «вызывай скилл при 1% шанса» | одна строка в контексте сессии с именами процессных скиллов, остальное — по описанию | строка — около 60 токенов, правило «1%» тратит контекст и спорит с инструкциями проекта. Замер: красный тест до кода — 0 из 2 без строки, 3 из 3 с ней, лишних срабатываний на простом вопросе нет |
| Идея | brainstorming: по одному вопросу до полной картины, пересказы по частям, дизайн-документ | `clarify-task`: изучить проект, одно сообщение — что понял, подходы с рекомендацией, не больше трёх вопросов | долгие интервью отвергнуты пользователем. Замер на расплывчатой просьбе: 0 из 3 до, 2 из 3 после |
| План | отдельный файл плана: карта файлов, интерфейсы, `Run`/`Expected`, Review Focus | тот же формат — в ledger задачи Tier 3 | формат взят почти целиком: у них такой план требовал одного раунда правок вместо двух–четырёх |
| Проверка плана | builder check — свежий субагент читает дизайн | `scope-challenger` вторым, отдельным вызовом | роль без Edit и Write по инструментам, а не по просьбе в промпте |
| Ветки | worktree с согласия, меню «слить / PR / оставить», удаление по набранному слову | то же меню; вопрос о ветках — один раз на проект; worktree — только когда одну область трогают двое | хук подсказывает агенту, что он на основной ветке: без него агент делал задачу прямо в `main` |
| Тест | «код до теста — удали и начни заново» | красный тест до кода; код, написанный раньше, остаётся, а тест доказывает себя, краснея на нарочно сломанном коде | удаление без слова человека спорит с нашими правилами подтверждения; доказательство через поломку даёт ту же гарантию |
| Отладка | корень до исправления, одна гипотеза, стоп после трёх | то же, плюс роль `investigator` для трудных случаев | порог совпал с нашими правилами остановки |
| Исполнение | без человека до конца: агент решает конфликты плана сам | после утверждения плана — то же, но push в любую ветку, слияние и публикация — только с человеком | у них «push в не-общую ветку — по нормам», то есть на усмотрение агента. У нас действие за пределами ветки — всегда человек |
| Ревью | ревью каждой задачи + финальное, до пяти раундов исправлений | отдельное ревью у рискованных задач (безопасность, API, схема, деньги, права) + финальное ветки, до трёх раундов | выбор пользователя: ревью каждой задачи умножает вызовы, а ошибки в механических задачах ловит финальное ревью |
| Долгая задача | `progress.md` и скрипт `task-done` пишут журнал | ledger и хук `ledger_log.py`, который сам пишет каждый вызов роли | проверено обрывом: новая сессия продолжила по ledger и не повторила ни одного вызова |
| Скилл после сжатия контекста | тест размера, длинное — в `references/` | то же | — |

## Что мы не взяли

- **«Вызывай скилл при 1% шанса»** и обязательный текст в начале каждой сессии — заменены одной строкой.
- **«Не останавливайся спросить человека»** в части действий за пределами ветки — у нас это всегда человек.
- **Удаление кода, написанного до теста**, — заменено доказательством через поломку.
- **`npm install` и коммиты без вопроса** при создании worktree — у нас установка зависимостей и коммит идут по просьбе.
- **Субагент, который «спрашивает и ждёт ответа»**, — субагент спросить пользователя не может; у нас он возвращает блок «НУЖНО РАЗРЕШЕНИЕ», и спрашивает главный диалог.
- **Визуальный компаньон** — локальный сервер с экранами для обсуждения дизайна.

## Где сильнее мы

- **Механическая защита.** Хуки на разрушение, `.env`, SQL без `WHERE`, force-push, удаление неслитой ветки, коммит кода без одобрения ревьюера. Правило, которое держится только на тексте, соблюдается по настроению.
- **Роли и зоны.** 19 ролей с матрицей прав; хук не пускает роль в чужую зону.
- **Внешние модели.** Две модели других вендоров на рискованном ревью, выбранные замером на своих дефектах.
- **Журналы.** Журнал привилегированных действий и журнал вызовов ролей.
- **Проверки поведения**, гоняемые перед каждым выпуском: защита, eval-сценарии инъекций и обхода подтверждения, вызов скиллов, ветки, тест сначала.

## Где сильнее они

- **Платформы** — 16, у нас механика только для Claude Code.
- **Масштаб и сообщество** — сотни контрибьюторов и внешний репозиторий поведенческих evals.
- **Глубина отдельных скиллов** — например, визуальный компаньон и подробные справочники по отладке.
