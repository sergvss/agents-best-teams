# Первый запуск и миграция

Путь от чистого проекта до работающей команды ролей, и что делать тем, кто применял шаблоны до версии 1.0.0.

---

> Установил плагином? Шаги 1-3 делает `/agents-best-teams:setup-agent-team`, шаг 4 уже выполнен. Ниже — что происходит под капотом и как сделать то же руками.

1. **Скопируй шаблоны** в свой проект — см. [install.md](install.md). Если нужна триангуляция, создай ещё и `agents.config` — см. [models.md](models.md); для Tier 1 и Tier 2 он не требуется
2. **Адаптируй плейсхолдеры** в каждом шаблоне:
   - `<your-project>` — название проекта
   - `<backend-framework>` — FastAPI / Django / Express / Rails / ...
   - `<frontend-framework>` — Vue / React / Svelte / ...
   - `<порт>`, `<ваш-бэк-порт>`, `<ваш-фронт-порт>` — порты твоих dev-серверов
   - `<ваш>` / `<ваша>` в строках описания стека — оставь один вариант из списка рядом, остальные удали

   После замены проверь что **все типы плейсхолдеров** заменены:
   ```bash
   # Подставь свою agents-директорию: .claude/agents/ для Claude Code,
   # .cursor/rules/ для Cursor, ~/.codex/skills/.../ для Codex, и т.д.
   AGENTS_DIR=".claude/agents"   # ← поменяй под свою платформу
   grep -rEn '<your-[a-z-]+>|<ваш[а-и]?>|<ваш-[а-яa-z-]+>|<backend-framework>|<frontend-framework>|<порт>|<reasoning-LLM[^>]*>|<быстрый[^>]*>|<мощный[^>]*>|<каталог-e2e>|<пути [^>]*>' "$AGENTS_DIR"
   # должно вернуть пусто — все плейсхолдеры заменены
   ```

   > Проверка ищет только **установочные** плейсхолдеры. Разметка вида `<что сделать>`, `<step>`, `<вердикт>` и `<PORT>` в командах `lsof -ti :<PORT>` — это места, которые агент заполняет по ходу задачи. Их заменять не нужно, и в проверку они намеренно не входят.

   Одного grep по скобкам мало: раздел «Неприкосновенные инварианты» в dev-ролях — это болванка **без скобок**, с примерами из типового стека. Оставить её хуже, чем оставить пустой раздел: роль в проекте без ORM будет требовать миграции через Alembic и добьётся своего.
   ```bash
   grep -rn 'Опиши здесь\|Примеры типичных\|Укажи здесь' "$AGENTS_DIR"
   # тоже должно вернуть пусто
   ```
   Инварианты выясняй из кода: какой префикс и формат тела у существующих эндпоинтов, как меняется схема БД, где проверяются права. Примеры, которых в проекте нет, — удалить.
3. **Настрой `pm-orchestrator.md`** — таблицу маршрутизации под свои реальные роли. Минимально: dev-агент + qa-тестер + оркестратор
4. **Поставь защитные hooks** — они уже реализованы, писать ничего не нужно:
   ```bash
   cp hooks/*.py <проект>/.claude/hooks/
   cp hooks/settings.example.json <проект>/.claude/settings.json
   # язык сообщений: по умолчанию английский
   printf 'ru\n' > <проект>/.claude/.abt-lang
   ```
   Копируй все `.py` разом: конфигурация ссылается на четыре хука, а `messages.py` нужен всем — в нём текст сообщений. Скопировать один `guard.py` — самая частая ошибка установки. Молча она не проходит: `guard.py` без `messages.py` падает с `ModuleNotFoundError`, а отсутствующий скрипт даёт «can't open file». Но упадёт это при первой же проверке команды, а не при установке, и связь с пропущенным файлом придётся восстанавливать по трассировке.

   ⚠ Вторая строка **затирает** `.claude/settings.json`, если он уже есть. Файл-пример состоит из единственного ключа `"hooks"`, так что при существующих настройках копировать поверх нельзя — перенеси в свой файл только блок `"hooks"`, оставив остальные ключи как были.

   Закрывают деструктив ФС, force-push, правку `.env`, SQL без WHERE и возвращают ролям ограничения, которые снимает поле `memory`. Только Python, без зависимостей. Подробности — `../hooks/README.md`
5. **Прогони eval-suite** из `../principles/10-eval-suite.md` — 5 базовых сценариев, 20-30 минут. Покажет дыры до того, как они выстрелят в проде

## Уже стоит предыдущая версия?

Обновление установленного — отдельная тема со своими ловушками: часть файлов вы адаптировали под проект, и перезаписывать их нельзя. Всё это в [update.md](update.md).

Коротко о терминологии, если вы читали старые версии: «GPT-консультант» и «внешние ревьюеры» теперь называются `reasoning-consultant` (разовая консультация до Tier 3) и SIDE-A / SIDE-B (триангулированное ревью после).
