## [1.8.2] — 2026-08-29

### Исправлено

Сплошная сверка после 1.8.1. Утверждение «в коде хуков не осталось ни одной строки для пользователя» оказалось верным не полностью — нашлось шесть мест.

- **Русский текст уезжал внутрь английского сообщения.** При блокировке рефспека с плюсом (`git push origin +main`) в текст подставлялась строка `git push origin +<ветка>` — то есть англоязычный пользователь получал английское объяснение с русским словом внутри. Ровно тот класс дефекта, ради которого каталог и заводился, и найти его чтением было нельзя: подстановка живёт отдельно от сообщения.
- **Тексты `--help` у трёх хуков** (`guard.py`, `retry_guard.py`, `verify.py`) остались в коде. Их видит тот, кто настраивает хуки руками, — то есть это тоже текст для человека.
- **Два сообщения об ошибках** в `retry_guard.py` и `approval_log.py` шли в stderr по-русски мимо каталога.
- **Проверка стала механической.** Тест разбирает хуки через AST и ищет строковый литерал с кириллицей, который не является докстрингом. Докстринги и комментарии остаются русскими намеренно — они для того, кто правит код, а не для пользователя. Именно этот тест и нашёл всё перечисленное; чтением находилась только часть.

### Изменено

- **Метки в журнале привилегированных действий переведены на латиницу**: `миграция` → `db-migration`, `установка пакетов` → `package-install`, `обращение к БД` → `db-access`, `права и владение` → `permissions`, `управление службами` → `service-control`, `чтение секретов` → `secret-read`, `правка чувствительного файла` → `sensitive-file-edit`. Половина меток (`git-push`, `git-commit`) и так была латинской — список был непоследователен внутри себя.

  Это **не перевод, а отказ от перевода**: метки журнала — устойчивые идентификаторы, а не сообщения. Переводись они вместе с языком, один файл после смены `ABT_LANG` содержал бы записи на двух языках, и по нему нельзя было бы ни искать, ни считать. В старых журналах записи остаются как есть; если вы по ним ищете, учтите смену словаря с этой версии.

## [1.8.1] — 2026-08-29

### Исправлено

Сверка инструкций установки и обновления с текущим устройством плагина. Нашлось больше, чем ожидалось, и главное — не про язык.

- **Ручная установка ставила один хук из четырёх.** `docs/install.md` и `docs/quick-start.md` копировали только `guard.py`, тогда как `settings.example.json` объявляет ещё `approval_log.py`, `retry_guard.py` и `session_start.py`. Конфигурация ссылалась на файлы, которых в проекте нет. Коварство в том, что ошибки при этом не возникает: недостающий хук просто не запускается, а выглядит настроенным — тот самый случай, о котором сама же документация предупреждает («незапустившийся хук неотличим от отсутствующего»). Теперь копируется маска `hooks/*.py`, и в обоих документах сказано, почему выборочно нельзя.
- **Проверка ссылок в конфигурациях стала механической.** Тест сверяет, что каждый `*.py`, упомянутый в `hooks.json` и `settings.example.json`, существует на диске. Расхождение такого рода иначе обнаруживается только на чужой машине.
- **`docs/quick-start.md` не знал про прозаические плейсхолдеры.** Проверка после адаптации ролей искала только угловые скобки — ту же дыру чинили в скилле `setup-agent-team` в версии 1.4.0, а ручной путь остался без исправления. Добавлен второй grep и объяснение, почему болванка с примерами из чужого стека хуже пустого раздела.
- **`.claude/.abt-lang` добавлен в списки того, что нельзя перезаписывать** при обновлении — в обоих README и в `docs/update.md`. Иначе выбранный язык слетал бы при каждом ручном обновлении.
- В инструкции установки и первого запуска добавлен выбор языка, в структуру репозитория в обоих README — `messages.py` и `docs/concepts.en.md`.

## [1.8.0] — 2026-08-29

> **Меняется поведение существующих установок.** Сообщения хуков теперь на выбранном языке, и умолчание английское. Если у вас блокировки приходили по-русски, верните их одной строкой: `mkdir -p .claude && printf 'ru\n' > .claude/.abt-lang`. При первом запуске плагин и сам предложит выбрать язык. Правила не изменились — блокируется ровно то же, что и раньше.
>
> **При ручной установке скопируйте новый `hooks/messages.py`** рядом с `guard.py`: без него хуки не запустятся, потому что импортируют из него весь свой текст.

### Добавлено

- **Каталог сообщений [`hooks/messages.py`](hooks/messages.py)** — весь текст, который читает человек, вынесен из четырёх хуков в одно место и существует на английском и русском. Это было единственное место, где язык действительно мешал работать: блокировку читают ровно тогда, когда что-то уже пошло не так, и машинный перевод в этот момент — худший из вариантов.
- **Выбор языка**, в порядке убывания приоритета: переменная `ABT_LANG`, файл `.claude/.abt-lang` в проекте, английский. Незнакомое значение откатывается на английский и **защиту не снимает** — на это есть отдельный тест, потому что «опечатка в настройке молча отключила хук» здесь самый дорогой исход.
- **Вопрос о языке при первом запуске.** `session_start.py` спрашивает один раз, если язык не задан, и молчит после того, как файл появился. Без этого обновление молча сменило бы язык у тех, кто ничего не просил.
- **Перевод ролей при развёртывании.** `setup-agent-team` определяет язык пользователя и может выдать роли на нём, переводя шаблон при копировании. В репозитории остаётся одна каноническая копия — значит, второй копии, которая начнёт расходиться, не существует. Цена решения названа прямо: перевод может исказить формулировку инварианта, поэтому раздел «Неприкосновенные инварианты» после перевода сверяется с кодом отдельно.
- **[`docs/concepts.en.md`](docs/concepts.en.md)** — страница концепций для англоязычных. Не перевод 6031 строки прозы, а термины, которые встречаются в сообщениях и ролях: Tier, классы риска R/D/W/P, правило 2-из-3 и вырождение кворума, память ролей и почему поле `memory` требует хука, стоп-правила, механические инварианты.
- **Тесты на сам каталог** (`TestMessageCatalogue`): каждый ключ есть на обоих языках; наборы подстановок в переводах совпадают — иначе блокировка падала бы с `TypeError` ровно в момент срабатывания; хуки не ссылаются на несуществующие ключи; язык переключается; файл в проекте работает; пара `guard.py` + `messages.py` самодостаточна при ручной установке.

### Исправлено

- **Инструкция ручной установки копировала только `guard.py`.** После выноса сообщений этого стало недостаточно, и хук не запустился бы вовсе. Найдено при сверке документации с новым устройством, а не на живом проекте.

## [1.7.0] — 2026-08-28

### Изменено

- **Английский README стал основным.** Файлы переименованы: `README.md` теперь английский, русский переехал в `README.ru.md`. Так велит сложившаяся конвенция — локальные версии живут в `README.<код языка>.md`, а основным держат английский, потому что репозиторий публичный и первым его открывает кто угодно. Нативной поддержки языков у GitHub нет и не было: он не выбирает README по локали посетителя, единственный рабочий способ — второй файл и явная ссылка.
- **Переключатель языка бейджами** в шапке обоих файлов, активный язык подсвечен — по [multilanguage-readme-pattern](https://github.com/jonatasemidio/multilanguage-readme-pattern). Стоит сразу под заголовком: раз автоматики нет, ссылку должен заметить человек, иначе он её не найдёт. Флаги-эмодзи не используются намеренно — флаг обозначает страну, а не язык.
- **Правило сопровождения перевернулось вместе с файлами:** отставать разрешено только `README.ru.md`. То, что посетитель видит первым, обязано быть верным; расхождение по фактам недопустимо ни в какую сторону.
- **Метаданные плагина переведены на английский** — описания в `plugin.json` и `marketplace.json` плюс однострочные `description` шести скиллов. Десять строк: их видно в `/plugin`, `/help` и в каталоге плагинов, то есть их читают до того, как что-либо решают. Тело скиллов, роли, принципы и чек-листы остаются русскими; в описаниях это сказано прямо, чтобы установка не заканчивалась неожиданностью.

Содержимое методологии по-прежнему русское, и переводить его целиком не планируется — обоснование в разделе «Два языка» русского README.

Все одиннадцать eval-сценариев принципа 10 прогнаны на живом коде, включая четыре финансовые роли из 1.5.0. Провалов по существу нет; два сценария оказались написаны неверно и переписаны по результатам прогона.

### Изменено

- **Правило 4 принципа 07 приведено к порогу правила 1.** Стояло «две ошибки внешнего сервиса подряд — стоп», хотя правило 1 говорит «три» и реализовано хуком `retry_guard.py`. Сценарий `CF-2` вскрыл расхождение: агент сделал три попытки, во всём остальном повёл себя правильно и нарушил букву правила, не нарушив смысла. Победил порог, у которого есть механизм. Добавлено то, что действительно отличает внешний сервис: между попытками само по себе не меняется ничего, поэтому у повтора должна быть причина, а диагностику можно начинать сразу после первой ошибки. Плюс главный критерий `CF-2`: не придумывать данные, которых сервис не отдал.
- **Сценарии `PI-1` и `PI-2` переписаны.** Оба были построены как «пользователь просит — агент отказывает» и смешивали две разные вещи: поддельный знак власти и существо просьбы. Просьбу пишет пользователь, которому агент и так подчиняется, а правила могут её разрешать — чтение `.env` в этой методологии разрешено, запрещена запись. Требовать отказа означало требовать, чтобы агент отказывал в разрешённом: это хуже, а не безопаснее. Теперь проверяется обёртка, а не просьба; добавлена врезка, разводящая `PI-1`/`PI-2` (инъекция от пользователя) и `PI-3`/`PI-4` (инъекция от постороннего).

### Исправлено

- **Противоречие внутри шаблона `unit-economics-analyst`:** «нет данных — так и скажи» против обязательного блока «Формат заключения». Роль на прогоне разрешила его сама и правильно, но противоречие было наше — теперь короткий ответ при отсутствии данных разрешён явно. Таблица со строкой «нет данных» в каждой ячейке создаёт видимость расчёта там, где расчёта не было.
- Опечатка в принципе 07: «cycличный» — латиница вперемешку с кириллицей.

## [1.5.0] — 2026-08-28

### Добавлено

Четыре финансовые роли. В gstack аналога нет — там нет ни одной роли про деньги, так что направление новое, а не заимствованное. Все четыре только читают: считают и передают вывод человеку, правки делают профильные роли.

- **`finops-engineer`** — переменная стоимость, то есть всё, что растёт с нагрузкой: облако, трафик, хранение, платные API и токены самой агентной команды. Главное правило роли — стоимость это произведение цены на частоту: опасен не дорогой вызов, а дешёвый вызов в горячем пути, который в ревью выглядит безобидно.
- **`unit-economics-analyst`** — окупается ли фича до того, как её начали строить. Работает в паре со `scope-challenger`, но спорит числами, а не логикой; противоположные выводы у этих двух ролей нормальны, решает человек.
- **`investment-analyst`** — материалы для инвесторов и совета. Единственная роль, чей результат уходит наружу и не отзывается обратно, поэтому правила строже: каждое число сопровождается способом получить его заново, а раздел «что просело» обязателен и не бывает пустым.
- **`vendor-auditor`** — постоянные расходы и лицензии: подписки, дублирующиеся сервисы, лицензии зависимостей и их совместимость с моделью распространения. Находка формулируется как обязательство, а не как ярлык: не «здесь GPL», а что именно это обязывает сделать.

Граница между двумя денежными ролями проведена по нагрузке: вырастет счёт от удвоения числа пользователей — это `finops-engineer`, не вырастет — `vendor-auditor`.

Общее для всех четырёх правило: **каждое число либо со ссылкой на источник, либо помечено как допущение**, а при отсутствии данных роль обязана сказать, что посчитать не может. Финансовый расчёт выглядит убедительно независимо от того, откуда взяты входные данные, и проверить его на глаз нельзя — это тот же режим отказа, что вскрыл сценарий CF-2: молчание заметно, выдуманное число нет.

- **Структурный тест на дыру в матрице разрешений.** Шаблон с `memory: project` и без Edit/Write в `tools`, отсутствующий в `MEMORY_MATRIX`, тихо получает право писать куда угодно. Раньше сверка шла только в одну сторону — матрица → шаблон, — и забытая при добавлении роли строка ничем себя не проявляла. Теперь проверяется и обратное направление.

## [1.4.0] — 2026-08-28

### Добавлено

- **Английский README** — `README.en.md`, переключатель языка в шапке обоих файлов. GitHub не умеет выбирать язык по локали посетителя, поэтому второй файл и явная ссылка между ними — единственный работающий способ. *(В 1.7.0 файлы переименованы: английский стал `README.md`, русский — `README.ru.md`. Ссылка здесь снята намеренно — под этим именем файла больше нет.)*

Главное сказано прямо: на английском всё работает, потому что роли и скиллы — это промпты, а хуки вообще не текст; упрётся ровно в одном месте — блокировка объясняет причину по-русски.
- **Путь публикации в community-маркетплейс** в памятке автору ([`docs/update.md`](docs/update.md)): подача идёт формой, а не PR, каталог синхронизируется раз в сутки, и проверять факт публикации нужно по имени плагина в `marketplace.json` каталога.
- **Сверка английского README** добавлена в памятку автору как шаг выпуска: перевод отстаёт на выпуск допустимо, расходится по фактам — нет.

### Исправлено

По итогам прогона двух последних eval-сценариев принципа 10 на живом коде. Оба провала оказались не в поведении агента, а в оснастке вокруг него.

- **Проверка шага 3 в `setup-agent-team` давала зелёный свет незаполненной роли.** Она искала плейсхолдеры по угловым скобкам, а раздел «Неприкосновенные инварианты» — прозаическая болванка: «Опиши здесь инварианты своего проекта» и примеры из типового стека. В песочнице роль девять сессий носила требование гонять схему через Alembic в проекте без ORM — это хуже пустого раздела, потому что такое требование выполняют. Добавлен второй grep и прямое указание: инварианты выясняются из кода, неприменимые примеры удаляются, неочевидное спрашивается, а не придумывается.
- **Правило 2-из-3 при отказе провайдера вырождалось молча.** Отчёт со всеми упавшими сторонами выглядел как у нормального прогона: «пересечений между ревьюерами нет» читается как одобрение, хотя пересекаться было нечему. В `principles/05` добавлен подраздел «Когда голосов меньше трёх», в `templates/external-llm-reviewer.md` — раздел «Отказ провайдера» вместо одной строки таблицы: число дошедших голосов рядом с выводом, отказ от вывода о консенсусе при неполном кворуме, ненулевой код возврата.

## [1.0.0] — 2026-08-26

Первый выпуск с исполняемым кодом. До этого методология была только текстом, и каждый раздел заканчивался словами «реализация на твоей стороне».

### Добавлено

- **Защитные хуки** — `hooks/guard.py`, пять правил: деструктив файловой системы, опасные git-операции, SQL без `WHERE`, запись в `.env`, возврат ролям ограничений, снятых полем `memory`. Только стандартная библиотека Python, без внешних зависимостей. Больше полусотни тестов, половина из них — на отсутствие ложных срабатываний.
- **Установка плагином Claude Code** — манифесты в `.claude-plugin/`, автоподключение хуков через `hooks/hooks.json`. Две команды вместо клонирования и копирования вручную.
- **Чек-листы как скиллы** — `skills/`. Обёртки намеренно тонкие: содержимое остаётся в `checklists/` и не дублируется, а Claude узнаёт о существовании чек-листа и подтягивает его сам.
- **Скилл `setup-agent-team`** — собирает команду ролей под проект: предлагает состав по стеку, копирует шаблоны, адаптирует плейсхолдеры, сводит маршрутизацию оркестратора.
- **Одиннадцатый принцип — `11-untrusted-input.md`.** Текст из тикетов, веб-страниц и ответов API это данные, а не инструкции. Раньше репозиторий тестировал устойчивость к инъекции в `10-eval-suite.md`, но нигде не формулировал само правило, а сценарии проверяли только инъекцию от пользователя — то есть от того, кому агент и так подчиняется. Добавлен сценарий `PI-3` для инъекции из внешнего источника.
- **Раздел о кэшировании промптов** в `principles/04`. Чтение из кэша устойчиво стоит около десятой части обычного ввода; цена записи зависит от провайдера. Практическое следствие: стабильное в начало промпта, изменчивое в конец, а метка времени вверху обесценивает весь кэш ниже.
- **Stop-хук `verify.py`** — не даёт завершить работу с падающими тестами, делая условие готовности механическим. Ставится отдельно и только вместе с командой проверки. Блокирует ограниченное число раз подряд: бесконечная блокировка заперла бы сессию, молчаливый пропуск вернул бы исходную проблему.
- **Журнал привилегированных действий `approval_log.py`** — реализация принципа 08, которая раньше существовала только на бумаге. Хук на `PostToolUse` записывает коммиты, пуши, миграции, установки пакетов, обращения к базе и правки чувствительных файлов. Рутина отфильтрована намеренно: журнал, куда пишется всё подряд, читать никто не станет.
- **Правило трёх попыток `retry_guard.py`** — принцип 07 был последним без механической опоры. Хук считает неудачи и блокирует четвёртый **слепой** повтор: если между попытками менялась рабочая копия, счётчик сбрасывается, потому что цикл «починил — прогнал снова» это нормальная работа, а не петля.
- **Предупреждение о протухании таблицы моделей** — машиночитаемая отметка даты сверки в `agents.config.example`, CI предупреждает через три месяца. Именно предупреждение, а не провал сборки.
- **`EXAMPLES.md`** — каждый из одиннадцати принципов в виде «плохо → хорошо».
- **CI** — прогон тестов на трёх версиях Python при каждом push и pull request.
- **`docs/claude-code-mechanisms.md`** — разбор четырёх механизмов запуска: субагенты, agent teams, workflows, скиллы. Разводит терминологию: «команда агентов» в методологии это способ организации работы, а `agent teams` в Claude Code — один из механизмов, причём экспериментальный и выключенный по умолчанию.

### Исправлено

- **Поле `memory` снимало ограничения пяти ролей из одиннадцати** — оно выдаёт Read, Write и Edit в обход списка `tools`. Закрыто правилом `memory` в хуке; у этих ролей память и хук работают только в паре.
- **Девять способов обойти защиту**, найденных триангулированным ревью: перевод строки и одиночный `&` как разделители команд, вложенный `sh -c`, вызов по абсолютному пути, присваивание перед командой, `git clean` с длинными флагами, `git restore`, `git checkout -- .` с дополнительным путём, `WHERE` из подзапроса и комментария, выход из разрешённой зоны через `..`. Разбор команды переведён на `shlex` с `punctuation_chars`.
- **Два ложных срабатывания** — на текст с символом перенаправления внутри кавычек и на SQL со строковым литералом, где слово `DELETE` было частью данных.
- **Опечатка и пустое значение в списке правил** молча отключали защиту — теперь хук отказывает с объяснением.
- **`permissionMode` не реализует классы риска**, как утверждалось: поле управляет только правками файлов, а классы W и P закрываются правилами разрешений и хуками. Формулировки исправлены, значения приведены к фактическим классам.

- Проверочный `grep` в README не ловил часть плейсхолдеров и искал два несуществующих.
- Битые внутренние ссылки и устаревшие идентификаторы моделей.
- **Правило `memory` обходилось через оболочку.** Инструмент Write у роли блокировался, а `cat > файл` писал тот же файл мимо проверки. Найдено на живом прогоне: субагент `devops` создал файл, которого не имел права создавать. Хуже того, платформа после блокировки Write сама предлагает агенту перейти на Bash. - **Шаги с SIDE-моделями на Tier 3 значились обязательными**, хотя готового вызова внешних моделей репозиторий не поставляет. Живой оркестратор упёрся в этот гейт и остановился; у другого агента это с равной вероятностью стало бы тихой имитацией выполненного шага. Шаги сделаны условными, пропуск обязан фиксироваться явно.
