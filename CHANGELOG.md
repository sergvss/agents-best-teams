# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по [семантическому версионированию](https://semver.org/lang/ru/).

## [1.0.0] — 2026-08-26

Первый выпуск с исполняемым кодом. До этого методология была только текстом, и каждый раздел заканчивался словами «реализация на твоей стороне».

### Добавлено

- **Защитные хуки** — `hooks/guard.py`, пять правил: деструктив файловой системы, опасные git-операции, SQL без `WHERE`, запись в `.env`, возврат ролям ограничений, снятых полем `memory`. Только стандартная библиотека Python, без внешних зависимостей. 43 теста, половина из них — на отсутствие ложных срабатываний.
- **Установка плагином Claude Code** — манифесты в `.claude-plugin/`, автоподключение хуков через `hooks/hooks.json`. Две команды вместо клонирования и копирования вручную.
- **Чек-листы как скиллы** — `skills/`. Обёртки намеренно тонкие: содержимое остаётся в `checklists/` и не дублируется, а Claude узнаёт о существовании чек-листа и подтягивает его сам.
- **Скилл `setup-agent-team`** — собирает команду ролей под проект: предлагает состав по стеку, копирует шаблоны, адаптирует плейсхолдеры, сводит маршрутизацию оркестратора.
- **`EXAMPLES.md`** — каждый из десяти принципов в виде «плохо → хорошо».
- **CI** — прогон тестов на трёх версиях Python при каждом push и pull request.

### Изменено

- **Выбор модели для ревью — по измеримому порогу, а не по названию тира.** Таксономия `top / strong / mid / light` заменена на `coding_index ≥ 74` для обычного ревью и `≥ 77` плюс `effort: high` для точек высокого риска. Причина: названия перестали означать уровень — модель Google с `flash` в имени обходит вчерашний флагман OpenAI по коду и стоит в 13 раз дешевле.
- **Конкретные модели вынесены в одно место** — `agents.config.example`. Из `principles/04` продублированная таблица убрана, чтобы протухала одна точка, а не две.
- **Шаблоны агентов** получили поля `permissionMode`, `maxTurns`, `effort`, `memory`; `browser-tester` — inline-описание Playwright MCP, чтобы браузерные инструменты не занимали контекст основной сессии.
- **`principles/09`** переписан на действующий контракт хуков: решение через `permissionDecision`, состав входного JSON, события сверх `PreToolUse`, типы хуков включая `agent`.
- **`principles/06`** дополнен описанием нативного поля `memory` и его скоупов.
- **`checklists/permission-checklist.md`** — добавлена матрица режимов и разбор конфликта `memory` с матрицей разрешений.

### Исправлено

- **Поле `memory` снимало ограничения пяти ролей из одиннадцати** — оно выдаёт Read, Write и Edit в обход списка `tools`. Закрыто правилом `memory` в хуке; у этих ролей память и хук работают только в паре.
- **Девять способов обойти защиту**, найденных триангулированным ревью: перевод строки и одиночный `&` как разделители команд, вложенный `sh -c`, вызов по абсолютному пути, присваивание перед командой, `git clean` с длинными флагами, `git restore`, `git checkout -- .` с дополнительным путём, `WHERE` из подзапроса и комментария, выход из разрешённой зоны через `..`. Разбор команды переведён на `shlex` с `punctuation_chars`.
- **Два ложных срабатывания** — на текст с символом перенаправления внутри кавычек и на SQL со строковым литералом, где слово `DELETE` было частью данных.
- **Опечатка и пустое значение в списке правил** молча отключали защиту — теперь хук отказывает с объяснением.
- **`permissionMode` не реализует классы риска**, как утверждалось: поле управляет только правками файлов, а классы W и P закрываются правилами разрешений и хуками. Формулировки исправлены, значения приведены к фактическим классам.
- Самопротиворечивое сообщение о блокировке: предлагаемая альтернатива сама блокировалась тем же правилом.
- Проверочный `grep` в README не ловил часть плейсхолдеров и искал два несуществующих.
- Битые внутренние ссылки и устаревшие идентификаторы моделей.

### Прочее

- README сокращён; подробности установки, настройки моделей и первого запуска вынесены в `docs/`.
- Иконка уменьшена с 1024×1024 до 512×512 — 605 КБ превратились в 104 КБ.
