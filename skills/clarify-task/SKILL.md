# Уточнить задачу без интервью

**Сначала смотри, потом спрашивай.** Прочитай файлы и код, которые просьба затрагивает. Не спрашивай то, что видно из проекта: язык, фреймворк, формат API, где тесты.

**Запрос полный** — делай; ключевой выбор назови одной строкой.

**Иначе — одно сообщение:**
1. **Что понял** — 2–4 строки своими словами вместе с найденным в проекте; ограничения, конфликты, путь дешевле.
2. **Подходы** — только при настоящей развилке: 2–3 варианта, у каждого «чем платим», и рекомендация с причиной.
3. **Вопросы** — не больше трёх, только меняющие результат, у каждого — что меняет ответ. Остальное реши сам и назови «моё решение».

Дальше — ответ пользователя, а не второй раунд вопросов. Потом: размер работы — это Tier; Tier 1–2 — в работу, Tier 3 — план по шаблону `planning-checklist`.

**Не делай:** допрос по одному вопросу; меню без рекомендации; дизайн-документ для Tier 1–2; правки до ответа, когда вопрос меняет результат.

Полный текст: `${CLAUDE_PLUGIN_ROOT}/checklists/clarify-task.md`

Если методология установлена копированием — файл лежит в `checklists/clarify-task.md` репозитория.
