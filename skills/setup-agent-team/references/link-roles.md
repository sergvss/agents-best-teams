# Проверка шага 4: роли сведены друг с другом

Часть шага 4 скилла `setup-agent-team`, вынесена по той же причине, что `adapt-roles.md`.

**Проверка шага** — глазами этот шаг не проверяется, поэтому командой (bash). Она предполагает установленного `pm-orchestrator`: на минимальном составе из трёх ролей его нет, и весь шаг 4 к такой команде не относится — маршрутизировать некому. Запустишь всё равно — `grep` пожалуется на отсутствующий файл, а `comm` перечислит все роли, и это будет выглядеть как «их не позовут никогда»:

```bash
comm -3 \
  <(ls .claude/agents/*.md | xargs -n1 basename | sed 's/\.md$//' | grep -v '^pm-orchestrator$' | sort) \
  <(grep -o '^| `[a-z0-9-]*`' .claude/agents/pm-orchestrator.md | tr -d '|` ' | sort)
```

Должно вернуть пусто. Слева окажутся роли, которых нет в маршрутизации, — их не позовут никогда; справа — те, что есть в таблице, но не поставлены: тупик при попытке делегировать.

Вторая команда проверяет половину пункта 3 — дыры: каждый каталог верхнего уровня с кодом должен встретиться в колонке «владеет файлами» хотя бы раз:

```bash
for d in $(git ls-files | grep '/' | grep -E '\.(py|js|ts|tsx|vue|go|rs|java|rb|php|cs)$' | cut -d/ -f1 | sort -u); do
  grep -q "\`$d/" .claude/agents/pm-orchestrator.md || echo "$d/: нет хозяина"
done
```

Пусто — у каждого каталога есть хозяин. Пересечения командой не ловятся: вложенные зоны с исключениями вроде «`client/` кроме `locales/`» законны, и подсчёт упоминаний давал бы ложную тревогу — так вышло на песочнице. Пересечения сверяй глазами по таблице.
