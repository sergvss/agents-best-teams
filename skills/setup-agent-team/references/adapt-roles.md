# Адаптация роли: перевод, плейсхолдеры, инварианты, проверка

> `${CLAUDE_PLUGIN_ROOT}` в этом файле не подставляется: Claude Code раскрывает его только в тексте самого скилла. Это каталог плагина — два уровня выше папки `references/`, в которой лежит этот файл.

Часть шага 3 скилла `setup-agent-team`. Вынесена в отдельный файл, чтобы скилл не дорос до 20 000 символов: после сжатия контекста Claude Code обрезает скилл на этой отметке, и хвост пропадает молча. Читается на шаге 3, для каждой копируемой роли.

**Если язык из шага 1 не русский — переведи роль при копировании.** В шапке переведённой роли поставь строку вида `<!-- переведено с templates/dev-backend.md; канон там -->`: если формулировка вызовет сомнение, будет куда посмотреть.

Что переводится, а что нет:

| Переводить | Оставить как есть |
|---|---|
| Текст роли целиком | `name`, `tools`, `model`, `permissionMode`, `maxTurns`, `effort`, `memory`, `color` |
| `description` во frontmatter | Пути, команды, имена файлов и полей |

`description` — проза, а не машинное поле: по нему роль находят и маршрутизируют. Русское описание в английской роли работает хуже, чем переведённое.

Перевод делается здесь, а не в репозитории, намеренно. В репозитории лежит одна каноническая копия, второй копии не существует — значит, ей нечему расходиться с оригиналом. Цена этого решения: перевод может исказить формулировку инварианта, поэтому раздел «Неприкосновенные инварианты» после перевода перечитай отдельно и сверь с кодом.

**Заменять нужно установочные плейсхолдеры:**

| Плейсхолдер | Чем заменить |
|---|---|
| `<your-project>` | название проекта |
| `<backend-framework>`, `<frontend-framework>` | реальные фреймворки |
| `<порт>`, `<ваш-бэк-порт>`, `<ваш-фронт-порт>` | реальные порты |
| `<пути бэкенда>`, `<пути фронтенда>`, `<пути тестов>` и прочие `<пути ...>` | реальные каталоги проекта. Это колонка «владеет файлами» в маршрутизации оркестратора, то есть сама граница зон: незаполненная, она обнуляет изоляцию, но выглядит настроенной |
| `<каталог-e2e>` | где в проекте лежат браузерные тесты: `e2e/` в корне или `tests/e2e/`. Это же значение определяет зону записи роли в хуке: если каталог называется не `e2e`, добавь его в `.claude/agents-best-teams.json` ключом `browser_tester_write_segments` |
| `<ваш>`, `<ваша>`, `<ваши>` | выбор из списка рядом |
| `<reasoning-LLM>`, `<мощный reasoning-LLM>`, `<мощный LLM>`, `<быстрый LLM>` | значение поля `model` |
| `<your-agent-dir>` | каталог агентов платформы |

В строках вида `Python 3.10+ / Node.js / Go / <ваш>` нужно **оставить один вариант** и удалить остальные вместе с плейсхолдером, а не дописывать значение рядом.

**Не трогать то, что заполняется по ходу работы.** В шаблонах есть разметка отчётов и рецептов — `<что сделать>`, `<step>`, `<вердикт>`, `<описание>`, `<PORT>` в командах вида `lsof -ti :<PORT>`. Это не плейсхолдеры установки, а места, которые агент заполняет во время задачи. Замена их сломает шаблон.

Различай по правилу: если значение одинаково для всех задач проекта — заменяй; если меняется от задачи к задаче — оставь.

**Есть плейсхолдеры без угловых скобок, и они опаснее.** Раздел «Неприкосновенные инварианты» в dev-ролях — это текст «Опиши здесь инварианты своего проекта. Примеры типичных:» и список примеров из типового стека: Alembic, централизованные guards, версионный префикс. Ни один grep по скобкам их не поймает.

Оставить этот раздел как есть — худший исход из трёх возможных. Пустой раздел просто бесполезен, а этот **активно врёт**: роль в проекте без ORM читает требование гонять схему через миграции и будет его выполнять.

Что делать:

1. **Выясни настоящие инварианты** — из кода, а не из головы: формат тела запроса и общий префикс у существующих эндпоинтов, единый формат ошибки, способ менять схему БД, где лежит проверка прав. Это то, что уже соблюдается в проекте; ты записываешь наблюдение, а не вводишь правило.
2. **Удали примеры, которых в проекте нет.** Нет миграций — нет подраздела про миграции.
3. **Если инвариант неочевиден из кода — спроси**, не угадывай. Инвариант, придуманный при установке, роль будет защищать наравне с настоящими.

**Файл настроек защиты — если проект не укладывается в умолчания.** Хук знает роли методологии и обычные раскладки тестов. Если E2E лежат не в `e2e/`, юнит-тесты называются иначе (`integration/`, `*.it.ts`) или ты добавил свою роль с полем `memory`, запиши это в `.claude/agents-best-teams.json`. Ключи и пример — `${CLAUDE_PLUGIN_ROOT}/hooks/README.md`, раздел «Файл настроек проекта». Запись в этот файл Claude Code покажет окном подтверждения, и это ожидаемо: файл расширяет зоны, решать должен человек. Для своей роли с памятью запись обязательна — без неё поле `memory` выдаст роли Write и Edit в обход её списка инструментов.

**Проверка шага:**

```bash
grep -rEn '<your-[a-z-]+>|<your [^>]*>|<paths [^>]*>|<ваш[а-и]?>|<ваш-[а-яa-z-]+>|<backend-framework>|<frontend-framework>|<порт>|<reasoning-LLM[^>]*>|<быстрый[^>]*>|<мощный[^>]*>|<каталог-e2e>|<пути [^>]*>|<[^>]*reasoning[^>]*>|<[^>]*LLM[^>]*>' .claude/agents/
grep -rn 'Опиши здесь\|Примеры типичных\|Describe here\|Typical examples' .claude/agents/
# Строки примеров, перенесённые из шаблона дословно, - не адаптированы
for r in dev-backend dev-frontend dev-database; do
  [ -f .claude/agents/$r.md ] || continue
  sed -n '/^## Неприкосновенные инварианты/,/^## [^#]/p' "${CLAUDE_PLUGIN_ROOT}/templates/$r.md" | grep '^- ' |
    grep -Fxf - .claude/agents/$r.md | sed "s/^/$r: /"
done
```

Первые две должны вернуть пусто. Третья ловит то, что вторая пропустит, если вводную строку раздела удалили, а примеры оставили: она ищет строки, совпадающие с примерами шаблона дословно. Её вывод — повод перечитать каждую строку, а не всегда ошибка: универсальное правило вроде «`SELECT COUNT(*)` перед массовым `DELETE`» законно остаётся дословным, а «JWT прикрепляется централизованно» в проекте без JWT — нет. Вторая и третья нужны ровно потому, что первая на этом разделе молчит: она проверяет форму плейсхолдера, а не его наличие. **Роль переведена** — третья проверка молчит всегда: дословных строк шаблона в переводе нет. Тогда раздел инвариантов сверь с шаблоном глазами, строка за строкой.
