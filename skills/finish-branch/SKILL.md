# Завершение работы в ветке

Влить работу решает пользователь, выбором в меню. Зелёные тесты — условие слияния, а не разрешение на него.

1. **Полный набор тестов проекта зелёный** — весь, не один свой файл. Красный — покажи падения и остановись.
2. **Ревью пройдено**, если его требует Tier. Включён шлюз ревью — коммит кода без одобрения `code-reviewer` откроет окно.
3. **Незакоммиченное** — покажи `git status --short` и спроси, коммитить ли.
4. **Меню одним сообщением:**
   1. Слить в `<основная>` локально
   2. Отправить ветку и открыть pull request
   3. Оставить ветку как есть

   Ты субагент — верни меню в отчёте, спросит главный диалог.
5. **Слить:** `git switch <основная>` → есть удалённый репозиторий — `git pull --ff-only` → `git merge --no-ff <ветка>` → полный набор тестов. Красный — стоп, ветку не удаляй. Зелёный — `git branch -d <ветка>` (не `-D`) и уборка своего worktree.
6. **Pull request:** `git push -u origin <ветка>` → `gh pr create` или средства платформы → ссылка. Ветку и worktree оставь.
7. **Оставить** — назови ветку и где worktree.

**Запреты.** Удалить неслитую работу — только если пользователь сам написал «удалить»: на `git branch -D` и `git worktree remove --force` хук откроет окно. Никогда `--force` по своей инициативе: отклонённый push значит, что удалённая ветка ушла вперёд, — разберись, а не перезаписывай. Чужие worktree не трогай.
