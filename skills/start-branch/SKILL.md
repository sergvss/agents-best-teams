# Начало работы в ветке

Любая правка кода крупнее пары строк — включая небольшую задачу Tier 1 — идёт в отдельной ветке: основная остаётся рабочей, откат — удаление ветки. Правка в пару строк — на текущей ветке. Порог ветки — не Tier: Tier решает, сколько процесса нужно, ветка — где работа живёт.

1. **Текущая ветка** — `git branch --show-current`. Не основная (`main`, `master` или та, на которую указывает `origin/HEAD`) — работай здесь.
2. **На основной — политика проекта:** `git config --get abt.branches`.
   - `auto` — создай ветку без вопроса; `off` — работай в основной.
   - Пусто — **заведи ветку сразу** (обратимо, основная останется чистой) и одним вопросом спроси пользователя: «Работать в отдельных ветках и дальше? Да — запомню. Нет — работаю в основной». Ответ запиши: `git config abt.branches auto` или `off`. Ответят «нет» — `git switch <основная>`, правки вернутся.
   - Ты субагент — вопрос верни блоком «НУЖНО РАЗРЕШЕНИЕ», а ветку заведи.
3. **`git switch -c <тип>/<короткое-имя>`** — `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`. Чужие незакоммиченные правки переедут вместе с тобой — в свои коммиты их не включай.
4. **Ledger заведён** — запиши туда ветку и основную.

**Worktree** — только когда одну область кода меняют двое параллельно, при двух подходах на сравнение или рискованном эксперименте. Иначе хватает зон ролей. Создавай встроенными средствами платформы — изоляция при вызове роли, `EnterWorktree` для своей сессии, — а не `git worktree add` руками.

Полный текст — когда что делать с worktree и почему так:
