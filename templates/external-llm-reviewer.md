# Паттерн: SIDE-модель как внешний ревьюер

Этот файл описывает **паттерн** подключения SIDE-модели (внешнего LLM-провайдера, отличного от твоего PRIMARY) для независимого ревью кода. Используется в схеме триангуляции — см. `../principles/05-triangulated-review.md`. Терминология PRIMARY / SIDE-A / SIDE-B — см. `../principles/01-philosophy.md` (глоссарий).

Конкретные модели SIDE-A и SIDE-B настраиваются в `agents.config` проекта (пример — в `../agents.config.example` в корне репо).

---

## Идея

У твоего PRIMARY-агента есть слепые пятна. SIDE-модель с другой архитектурой находит другие классы проблем. Вызываешь её через HTTP API, получаешь структурированный отчёт, сравниваешь с PRIMARY-ревью.

---

## Что нужно для реализации

1. **API-ключ** SIDE-провайдера (OpenAI / Google AI / Anthropic / Mistral / xAI / OpenRouter — любой с chat completions API). Хранится в `.env`, не в `agents.config`.
2. **CLI-скрипт или функция**, которая:
   - Принимает diff как входные данные
   - Проверяет diff на секреты до отправки — см. «Секреты до отправки»
   - Формирует промпт
   - Делает HTTP-запрос к API
   - Возвращает структурированный ответ

3. **Опционально:** агрегатор, который сводит отчёты нескольких ревьюеров.

---

## Секреты до отправки

Diff уходит к двум сторонним провайдерам и к шлюзу вроде OpenRouter. Если в коммит случайно попал ключ или пароль, он скомпрометирован в момент отправки: отозвать запрос нельзя. Защита `.env` на уровне файлов (принцип 09) этого не ловит — секрет записан прямо в код. Поэтому скрипт проверяет **весь текст diff** до вызова API: добавленные, удалённые и контекстные строки. Удалённая строка с секретом раскрывает его так же, как добавленная.

| Режим | Нашёлся секрет |
|---|---|
| Шлюз коммита | Коммит отклонён с отдельным кодом возврата, моделям **ничего не отправлено**. Секрет в коммите — ошибка всегда, ревьюить такой diff незачем |
| Ручной запуск ревью | Секрет заменён на `[REDACTED]`, в выводе перечень замен — номера строк, не значения |
| Ложное срабатывание | Пропуск только решением человека: переменная окружения, которую агент сам не ставит |

```python
import re

# Закрытые ключи и токены с узнаваемым префиксом — секрет в любом контексте.
# Ключ PEM захватывается целиком до END (или до конца текста, если END нет):
# иначе замена скроет только первую строку, а тело ключа уйдёт провайдеру
TOKEN = re.compile(
    r"(?s:-----BEGIN [A-Z ]*PRIVATE KEY-----.*?(?:-----END [A-Z ]*PRIVATE KEY-----|\Z))"
    r"|\b(?:sk-(?:or-v1-|proj-|ant-)?|ghp_|github_pat_|xox[abprs]-|y0_|AQVN)[A-Za-z0-9_\-]{16,}"
    r"|\bAKIA[0-9A-Z]{16}\b|\bAIza[0-9A-Za-z_\-]{35}|\bt1\.[A-Za-z0-9_.\-]{20,}"
)
# Строковый литерал, присвоенный переменной или ключу JSON/YAML с «секретным» именем.
# Экранированная кавычка внутри значения его не обрывает. Пробелы — [ \t], не \s:
# иначе redact по всему тексту ловил бы перенос строки, а построчный find_secrets — нет
ASSIGN = re.compile(
    r"""(?i)(?:password|passwd|secret|token|api_?key|private_?key)\w*["']?[ \t]*[:=][ \t]*(["'])((?:\\.|(?!\1).)*)\1"""
)
# Имя переменной окружения — ЗАГЛАВНЫЕ с хотя бы одним подчёркиванием (OPENROUTER_API_KEY).
# Без подчёркивания "ABCD1234SECRET" прошёл бы как имя. Отдельный шаблон без (?i) намеренно
ENV_NAME = re.compile(r"[A-Z][A-Z0-9]*(?:_[A-Z0-9]+)+")


def is_secret_value(value: str) -> bool:
    # Короткие значения, подстановки ${...} и имена переменных окружения — не секрет
    return len(value) >= 8 and "${" not in value and not ENV_NAME.fullmatch(value)


def find_secrets(diff: str) -> list[int]:
    """Номера строк diff с похожим на секрет. Сами значения не возвращаются."""
    hits = []
    for n, line in enumerate(diff.splitlines(), 1):
        if TOKEN.search(line) or any(is_secret_value(m.group(2)) for m in ASSIGN.finditer(line)):
            hits.append(n)
    return hits


def redact(diff: str) -> str:
    diff = TOKEN.sub("[REDACTED]", diff)

    def hide(m: re.Match) -> str:
        if not is_secret_value(m.group(2)):
            return m.group(0)
        # Заменяется только значение, имя ключа остаётся для контекста ревью
        start, end = m.start(2) - m.start(), m.end(2) - m.start()
        return m.group(0)[:start] + "[REDACTED]" + m.group(0)[end:]

    return ASSIGN.sub(hide, diff)
```

Чтение из окружения (`os.getenv(...)`, `process.env.X`) шаблон присваивания не задевает: значение там не строковый литерал. Подстановки `${VAR}` и `${{ secrets.X }}`, пустые и короткие значения, строка вроде `api_key_env = "OPENROUTER_API_KEY"` пропускаются через `is_secret_value`.

**Грабли, на которых это уже ломалось:**

- **Регистр.** Если собрать всё одним шаблоном с `(?i)`, исключение «имя переменной окружения — только заглавные» начинает пропускать настоящий пароль из строчных букв. Проверка имени должна быть регистрозависимой: отдельный шаблон или `(?-i:...)`.
- **Сломанный сканер не падает, а молчит.** Тесты нужны в обе стороны — ловит и не ловит — и должны идти в CI. Фальшивые секреты в самих тестах разбивай символом, который убирается при запуске, иначе шлюз отклонит собственный файл тестов.
- **Ложные срабатывания ищи до того, как они начнут блокировать коммиты.** Дешёвый способ — прогнать сканер по всему репозиторию как по добавленному diff.
- **Не печатай найденное.** Отчёт шлюза с самим значением секрета утекает в лог и в контекст агента — номер строки достаточен.

**Граница:** секрет, похожий на имя переменной окружения (`"SUPER_SECRET_123"`), пропускается — по одному значению их не различить. Значение без кавычек (`password: hunter2` в YAML) шаблон присваивания не видит. Шаблон на любое значение после `:` или `=` дал бы ложные срабатывания на каждое `token = self.token`. Токены с префиксом ловятся и без кавычек.

## Пример CLI-обёртки (псевдокод)

```python
import httpx
import json
import re
import sys

from secrets_scan import find_secrets, redact  # сканер из раздела «Секреты до отправки»

VERDICTS = {"approve", "changes_requested", "blocked"}


class UnusableResponse(Exception):
    """Ответ пришёл, но голосом не считается — это отказ стороны."""


def review_diff(diff: str, api_key: str, model: str, base_url: str) -> dict:
    # Последний рубеж: секрет не уходит, даже если вызывающий код не проверил diff
    diff = redact(diff)
    prompt = build_review_prompt(diff)
    
    response = httpx.post(
        f"{base_url}/chat/completions",
        headers={"Authorization": f"Bearer {api_key}"},
        json={
            "model": model,
            "messages": [{"role": "user", "content": prompt}],
            "response_format": {"type": "json_object"},
        },
        timeout=60,
    )
    response.raise_for_status()
    
    try:
        choice = response.json()["choices"][0]
        content = choice["message"]["content"] or ""
    except (KeyError, IndexError, TypeError, ValueError):
        raise UnusableResponse("в ответе нет choices/message/content")
    # Часть провайдеров отдаёт content списком частей — такой ответ тоже не голос
    if not isinstance(content, str):
        raise UnusableResponse("content не строка")

    # Оборванный ответ может случайно разобраться, но смотрела модель не всё
    if choice.get("finish_reason") == "length":
        raise UnusableResponse("ответ оборван по лимиту токенов")
    # Обрамление ```json ... ``` модель ставит почти всегда — снять до разбора
    content = re.sub(r"^```\w*\s*|\s*```$", "", content.strip())
    try:
        result = json.loads(content)
    except json.JSONDecodeError as e:
        raise UnusableResponse(f"ответ не JSON: {e}")
    # Без допустимого вердикта ответ нельзя засчитать ни как одобрение, ни как блок
    if not isinstance(result, dict) or result.get("verdict") not in VERDICTS:
        raise UnusableResponse("нет допустимого verdict")
    return result


if __name__ == "__main__":
    diff = sys.stdin.read()  # или из файла

    # Ручной прогон: секреты заменяются до отправки. Шлюз коммита вместо этого
    # выходит с отдельным кодом при любой находке и не вызывает API вовсе
    if lines := find_secrets(diff):
        print(f"SIDE: секреты заменены на [REDACTED], строки diff: {lines}", file=sys.stderr)
        diff = redact(diff)

    try:
        result = review_diff(diff, api_key=..., model=..., base_url=...)
    except UnusableResponse as e:
        # Громкий отказ стороны: голос не засчитан; здесь же сохрани сырой ответ в файл для разбора
        print(f"SIDE: отказ — {e}", file=sys.stderr)
        sys.exit(2)
    print(json.dumps(result, indent=2, ensure_ascii=False))
```

## Чему научила практика

Ниже — то, что выяснилось при реальной эксплуатации этого паттерна, а не при его проектировании. Каждый пункт стоил одного прогона.

**Модель обернёт JSON в тройные кавычки, что бы ты ни написал в промпте.** Снимай обрамление перед разбором, иначе половина ответов будет теряться на ровном месте.

**Запрети пустой `approve` явно.** Формулировка «если дифф большой, а сказать нечего — перечисли в notes, что именно ты проверил» превращает бесполезное «одобряю» в проверяемый отчёт. Без неё модель ниже порога отвечает одним словом, и понять, смотрела она вообще или нет, невозможно.

**Скрипт не должен выносить вердикт.** Соблазн посчитать 2-из-3 автоматически велик, но сопоставлять формулировки блокеров разных моделей — это выдумывать совпадения. Скрипт собирает голоса и печатает их рядом; правило применяет PRIMARY, складывая со своим ревью.

**Пересортируй находки по достижимости.** Внешний ревьюер ранжирует по тяжести механизма, потому что продукта не знает. На практике настоящий воспроизводимый баг приходил у него в заметках, а в блокерах стояло теоретически возможное состояние, до которого пользователь не доживёт. Это не повод игнорировать — это повод пересортировать.

**Проверяй утверждения о платформе.** Внешние модели уверенно заявляют о версиях, полях API и поведении инструментов то, чего не могут знать. Из трёх блокеров, связанных с платформой, два оказались неверны — и оба звучали одинаково убедительно.

**Один упавший ревьюер — это уже не триангуляция.** Обрабатывай отказ громко, а не молча продолжай с одним голосом.

**Считай размер до вызова.** Дифф больше полутора тысяч строк модель читает по диагонали. Дешевле разбить на части, чем получить обзорный ответ за те же деньги.

## Вызов из агента

```bash
# Получить diff
git diff main...HEAD > /tmp/review.diff

# Вызвать SIDE-A (имя скрипта/путь — на твой выбор; пример для Claude Code)
python3 <your-agent-dir>/scripts/llm/review.py \
  --diff /tmp/review.diff \
  --role side-a \
  --output /tmp/review-side-a.json

# Аналогично для SIDE-B
python3 <your-agent-dir>/scripts/llm/review.py \
  --diff /tmp/review.diff \
  --role side-b \
  --output /tmp/review-side-b.json

# Показать результат
cat /tmp/review-side-a.json | python3 -m json.tool
```

Конкретный провайдер и model id для каждой роли читаются из `agents.config` (секции `[side_a]` и `[side_b]`).

## Агрегация результатов (правило 2-из-3)

После получения трёх отчётов (PRIMARY + SIDE-A + SIDE-B):

```python
def aggregate_reviews(primary: dict, side_a: dict, side_b: dict) -> dict:
    all_blockers = primary["blockers"] + side_a["blockers"] + side_b["blockers"]

    # Найти blockers, о которых сообщили 2+ ревьюера
    confirmed_blockers = find_consensus(all_blockers, min_count=2)

    # Blockers только от одного — пометить как "требует проверки"
    unconfirmed = find_unique(all_blockers)

    return {
        "consensus_blockers": confirmed_blockers,    # обязательно фиксить
        "unconfirmed_blockers": unconfirmed,          # проверить вручную

    }
```

## Что делать с результатами

| Ситуация | Действие |
|---|---|
| Blocker подтверждён 2-3 ревьюерами | Фиксить обязательно, это реальная проблема |
| Blocker только у одного | Изучить вручную, вероятен false positive |
| Только warnings | Взвесить, нужны ли правки до мержа |
| Провайдер недоступен или ответ непригоден | Продолжить с оставшимися, но пересчитать кворум — см. ниже |

### Отказ провайдера

Продолжить с оставшимися ревьюерами мало: отчёт обязан показать, что голосов пришло меньше, чем планировалось.

- **Непригодный ответ — тот же отказ.** Провайдер ответил, но ответ не разбирается, в нём нет допустимого `verdict` или он оборван — голос не засчитывается. Засчитать его как «ответил, замечаний нет» — то же молчание, выданное за одобрение.

- **Число дошедших голосов — рядом с выводом.** Ошибку конкретной стороны видно, но сводка ниже считает только по успешным ответам и об этом не предупреждает.
- **Молчание не равно «блокеров нет».** Формулировки вроде «пересечений между ревьюерами нет» при двух отказах читаются как одобрение, хотя пересекаться было нечему.
- **Меньше трёх голосов — консенсуса нет.** Не пиши «проверено тремя», не подводи итог по правилу 2-из-3; скажи, что триангуляция не состоялась, и предложи продолжить базовым ревью PRIMARY.
- **Код возврата ненулевой, если не ответил никто.** Иначе вызывающая сторона примет провал за успешный прогон.

Одной попытки на сторону достаточно: повтор при недоступном провайдере — это петля retry, которую запрещает принцип 07.

### BLOCK, который ссылается на несуществующий код

Этот раздел нужен, если SIDE-BLOCK останавливает коммит или push автоматически, без PRIMARY. SIDE-модель видит только ханки diff. Отсюда класс ложных блокеров «нет в diff — значит нет в коде»: вызов виден, объявление строкой выше ханка — нет, и модель пишет «UnboundLocalError» или «нет проверки на None». На большой правке дешёвая модель так блокирует каждый раунд, и готовая работа не уезжает, пока проверку не выключат.

Право вето сохраняется, но BLOCK обязан ссылаться на код, который существует:

1. **Проверочный запрос той же модели.** Получив BLOCK, скрипт отправляет ей полные тексты названных файлов на отправляемом ref (у большого файла — окно вокруг места). Файлы уходят провайдеру так же, как diff, — прогони их через тот же `redact` из «Секретов до отправки». По каждому блокеру модель отвечает `CONFIRM` с номером строки и дословной цитатой либо `RETRACT`.
2. **Цитату сверяет код, не человек и не модель.** Подтверждён хотя бы один блокер — HALT, как раньше. Все отозваны или цитаты не сошлись — вердикт понижается до WARN, громко, с перечнем претензий и причин. Понижения до нуля нет — см. принцип 05, «Находка, которую не удалось воспроизвести».
3. **Сбой проверки — fail-closed.** Сеть упала, ответ непригоден — BLOCK остаётся. Понижение бывает только по итогам состоявшейся проверки.

```python
def citation_holds(file_text: str, line: int, quote: str, window: int = 2) -> bool:
    # Цитата сверяется без учёта пробелов в окне вокруг названной строки
    norm = lambda s: " ".join(s.split())
    lines = file_text.splitlines()
    around = "\n".join(lines[max(0, line - 1 - window): line + window])
    return bool(norm(quote)) and norm(quote) in norm(around)
```

Это не нарушает правило «скрипт не выносит вердикт»: скрипт проверяет факт — есть ли такая строка, — а не сопоставляет смысл разных ревью.

**Граница:** сверка ловит ссылку на несуществующий код, но не неверное рассуждение о существующем. Если модель подтвердит выдумку настоящей строкой, BLOCK устоит, и его разбирает человек.

**Диапазон ревью — то, что уходит.** В pre-push хуке ревьюй `remote_sha..local_sha` из stdin хука, для новой ветки — от merge-base. Не `origin/main..HEAD`: тогда `git push origin <sha>:main` ревьюит весь локальный HEAD, и большую правку нельзя приземлить частями. При верном диапазоне каждая порция ревьюится целиком.

**`git diff -W` на огромном файле.** Контекст функции на файле в 10 тысяч строк с одним классом сливает два далёких ханка в один пролёт на тысячи строк, и размер запроса растёт в десятки раз. Считай размер до вызова и дроби отправку по коммитам.

## Ограничения паттерна

- SIDE-модель не знает инвариантов твоего проекта (если не вписать в промпт). PRIMARY-ревьюер остаётся единственным с полным контекстом.
- Большие diff дорого отправлять — ограничь размер (например, первые 3000 строк).
- Разные провайдеры имеют разные rate limits и стоимость — учитывай в `[budget]` секции `agents.config`.
- Ответ может оказаться непригодным: не JSON, нет `verdict` из допустимых, обрыв по `finish_reason=length`. Это отказ стороны, а не голос — см. «Отказ провайдера». Сырой ответ сохрани в файл для разбора, стоимость учти в бюджете.

## Хранение API-ключей

API-ключи SIDE-провайдеров — в `.env` / переменных окружения. Никогда в коде, никогда в `agents.config`, никогда в git. Пример:

```bash
# .env (в .gitignore!)
OPENROUTER_API_KEY=sk-or-...   # один ключ ко всем моделям сразу
```
