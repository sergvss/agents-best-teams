# Шаблоны ролей

Двадцать ролей. Ставить все сразу не нужно и вредно — это тот самый оверхед, против которого написана методология. Минимальный работающий состав: **один dev-агент под основной стек, `qa-tester`, `code-reviewer`**; остальное добавляется, когда появляется нужда.

Разворачивает и адаптирует их скилл [`setup-agent-team`](../skills/setup-agent-team/SKILL.md): он читает стек проекта, предлагает состав, подставляет плейсхолдеры и, если нужно, переводит роли на язык пользователя. Копировать руками тоже можно — [docs/install.md](../docs/install.md).

## Кто делает

Правят код в своей зоне. Полный набор Edit и Write не у всех: `devops` и `local-sysops` меняют только существующие файлы (без Write), `browser-tester` пишет тест-артефакты, но продуктовый код не правит (без Edit). Точная матрица — [`checklists/permission-checklist.md`](../checklists/permission-checklist.md).

| Роль | Зона |
|---|---|
| [`dev-backend`](dev-backend.md) | Роутеры, модели, схемы, миграции, интеграции |
| [`dev-frontend`](dev-frontend.md) | SPA: компоненты, стейт, роутинг, HTTP-клиент |
| [`dev-database`](dev-database.md) | Схема БД, миграции, индексы, оптимизация запросов |
| [`qa-tester`](qa-tester.md) | Пишет и прогоняет тесты, проверяет регрессии |

## Кто смотрит

Ни Edit, ни Write: возвращают находку и передают её профильной роли. Это не формальность — ревьюер, который сам чинит найденное, перестаёт быть независимым мнением, а расследователь, который сам чинит, чинит симптом.

| Роль | Что ищет |
|---|---|
| [`code-reviewer`](code-reviewer.md) | Независимая проверка перед мержем |
| [`security-reviewer`](security-reviewer.md) | Авторизация, ввод, секреты, зависимости |
| [`design-reviewer`](design-reviewer.md) | Состояния интерфейса, вёрстка, доступность |
| [`investigator`](investigator.md) | Диагноз багам, не принадлежащим ни одной зоне |
| [`scope-challenger`](scope-challenger.md) | Надо ли делать это вообще — **до** декомпозиции |

## Кто считает

Тоже только читают. Общее правило: каждое число либо со ссылкой на источник, либо помечено как допущение, а без данных роль обязана сказать, что посчитать не может.

| Роль | Чьи деньги |
|---|---|
| [`finops-engineer`](finops-engineer.md) | Переменная стоимость: растёт с нагрузкой |
| [`vendor-auditor`](vendor-auditor.md) | Постоянная: подписки, лицензии зависимостей |
| [`unit-economics-analyst`](unit-economics-analyst.md) | Окупится ли фича — до постройки |
| [`investment-analyst`](investment-analyst.md) | Метрики и материалы для инвесторов |

## Что важно знать до правки шаблона

**Поле `memory` выдаёт Read/Write/Edit в обход списка `tools`.** Для роли, у которой их нет намеренно, это снимает её главную гарантию. Возвращает ограничение правило `memory` из [`../hooks/guard.py`](../hooks/guard.py) — то есть у читающих ролей память работает **только вместе с хуком**. Разбор — [`checklists/permission-checklist.md`](../checklists/permission-checklist.md).

**Раздел «Неприкосновенные инварианты» в dev-ролях — болванка.** В нём примеры из типового стека, и это плейсхолдер без угловых скобок: grep по `<...>` его не найдёт. Оставить как есть хуже, чем оставить пустым — роль в проекте без ORM будет требовать миграции через Alembic и добьётся своего. Инварианты выясняются из кода.

**Часть полей frontmatter не применяется к тиммейтам** в agent teams Claude Code — `skills`, `mcpServers`, `permissionMode`. Разбор — [`docs/claude-code-mechanisms.md`](../docs/claude-code-mechanisms.md).
