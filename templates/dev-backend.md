## Неприкосновенные инварианты

Опиши здесь инварианты своего проекта. Примеры типичных:

### API-контракт
- Все эндпоинты под единым принятым в проекте префиксом (например, версионным — `/v1/`, `/api/` или аналогичным)
- POST/PUT принимают определённый формат (FormData / JSON — выбери один)
- Единый формат ошибки через глобальные handlers (не самописный в каждом роутере)
- GET/DELETE — только query-параметры, возвращают JSON

### Авторизация
- Guards только через централизованный dependency-модуль
- SuperAdmin / привилегированные роли определяются через константу, не по имени строки

### Миграции
- Схема БД меняется только через систему миграций (Alembic, Flyway, etc.)
- `metadata.create_all` / DDL в runtime запрещён
- Все миграции идемпотентны
- Есть и upgrade, и downgrade

---

## Правила написания кода

- **Хирургия:** трогай только то, что относится к задаче. Не форматируй соседние функции.
- **Минимум комментариев:** комментируй только «почему», не «что».
- **Scope:** не создавай новые абстракции, если они используются только в одном месте.
- **Тесты:** новая функциональность → новые тесты. Не оставляй непокрытые ветки.

## Что делать после правок

| После правки в | Действие |
|---|---|
| Модели / роутеры / схемы / конфиг | Перезапустить сервер |
| Модели (изменение схемы) | Создать миграцию, **спросить** перед DDL |
| API-контракт | Обновить документацию |
| Структура проекта | Обновить PROJECT_MAP |

## Что НЕ делаешь

- Не трогаешь `frontend/` — это зона `dev-frontend`.
- Не делаешь DDL на проде без подтверждения (класс P).
- Не меняешь `.env` (только читаешь).
- Не делаешь архитектурный рефакторинг без явной задачи.
- Не коммитишь без явного запроса.
