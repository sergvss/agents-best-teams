# 03 — Классы риска действий

## Зачем

Просить подтверждение на каждый шаг — это шум, который приучает игнорировать. Никогда не просить подтверждения — это катастрофа, которую ждёшь. Классы риска — промежуточное решение: **подтверждение ровно там, где оно стоит своих прерываний**.

---

## Четыре класса

### R — Read (чтение)

**Что входит:**
- Чтение файлов, каталогов, БД-запросы SELECT
- `git status`, `git diff`, `git log`
- `curl` к локальным сервисам (health-check, API)
- Снимки экрана, accessibility tree (Playwright snapshot)
- Просмотр сетевых запросов, консоли браузера

**Подтверждение:** нет — выполнять сразу.

**Почему:** операция полностью обратима, не меняет состояние. Задержки нет смысла.

---

### D — Draft (черновик, локально-обратимо)

**Что входит:**
- Редактирование и создание файлов в репозитории (кроме `.env*`)
- Написание тестов, документации
- Создание файла миграции (не её применение)
- Клик/ввод в браузере в тестовом окружении
- Локальный запуск тестов

**Подтверждение:** нет — действие обратимо через `git checkout` или `git clean`.

**Почему:** всё это живёт в рабочей копии. Git — встроенный undo.

---

### W — Write (общее состояние)

**Что входит:**
- `git commit`, `git push`
- Применение миграций (например, `alembic upgrade head`, `npx prisma migrate deploy`, `rails db:migrate`)
- Установка зависимостей (`npm install`, `pip install` глобально)
- Регистрация MCP-серверов в user-конфиге
- Обновление общих конфигурационных файлов

**Подтверждение:** да, если пользователь не дал явное разрешение в текущем диалоге.

**Почему:** действие затрагивает состояние, которое видят другие (общий репозиторий, окружение). Откат требует усилий.

---

### P — Privileged (привилегированные)

**Что входит:**
- DDL на боевой БД (`DROP`, `TRUNCATE`, `ALTER TABLE`)
- Правка `.env*` файлов
- `git push --force`, удаление веток
- Операции с реальными платёжными данными
- Массовая рассылка уведомлений
- Удаление пользователей
- Любые операции от имени администратора в боевой системе

**Подтверждение:** всегда — даже если «разрешили раньше». Переподтверждать каждый раз.

**Почему:** эти действия либо необратимы, либо их последствия ощущают живые пользователи. «Я же сказал можно» — не защита. Протокол есть протокол.

---

## Таблица для быстрого выбора

| Действие | Класс | Подтверждение |
|---|---|---|
| `git diff`, `cat file.txt`, `curl localhost` | R | Нет |
| Создать/отредактировать файл в репо | D | Нет |
| Запустить тесты локально | D | Нет |
| `git commit` | W | Да (если не было разрешения) |
| `pip install` глобально | W | Да |
| Применение миграций схемы БД (любой migration tool) | W | Да |
| `git push --force` | P | Всегда да |
| DDL на продовой БД | P | Всегда да |
| Правка `.env` | P | Всегда да |
| Удаление пользователя через API | P | Всегда да |

---

## Правило неопределённости

Если не уверен в классе — применяй более строгий.

```
R → D → W → P
          ↑
    "если не уверен"
```

Лучше один раз лишний раз спросить, чем не спросить там, где надо было.

---

## Антипаттерн: «пользователь разрешил раньше»

```
# Диалог, который кажется безопасным, но не является
Пользователь: "да, делай миграции без вопросов"
Агент: [3 часа спустя, в другом контексте задачи]
       DROP TABLE users;  ← Privileged, нужно переподтверждение
```

Для класса P — контекст сессии не имеет значения. Каждое действие подтверждается отдельно.
